# MFEM 自主求解任务清单

**目标**　让智能体从一份 Markdown 问题说明出发，自主生成网格和 MFEM 求解程序，交付经独立核验的数值结果。先用 MFEM 官方算例验证全流程，再扩展到 MiniApps 和实际的多物理场耦合。

## 组会要求

1. 对照 GitHub 代码讲清整体设计，说明各模块的目的、输入、输出和能力边界。修正汇报里的术语和实验口径。
2. 把几何描述、初始网格生成、有限元离散、程序生成、组装、求解、复核与可视化串起来。智能体要能调用网格工具，编写 MFEM `main`、右端项及其他辅助函数，并根据问题选择组装方式、求解器和预条件子。
3. 先在 MFEM 官方 `examples` 上展示自主求解，记录官方输出作为独立对照。重点验证生成程序是否忠实表达给定的方程和边界条件，再验证数值解的精度。
4. 解释无解析真解时依据什么验收，以及 CFAC 的能量范数、证书和适用条件。对于时变、流体和耦合模型，分别定义有物理意义的检验指标。
5. 基础流程跑通后扩展到 MiniApps 和真正的耦合问题。热传导、波动与弹性等独立方程族可作为中间测试。

下文的优先级、首个算例与具体交付要求是执行计划。首轮建议选择 **MFEM Example 1 的二维 Poisson 问题**，把官方基线脚本中的常数源项 `f = 1` 写进规格。比较离散解时，用同一网格、有限元阶次和边界条件运行两份程序。[现有基线脚本](../scripts/run_ex1_baseline.sh) · [实现现况](IMPLEMENTATION_STATUS.md)

## P0 · 首个可复现的自主求解演示

| 待办 | 需要解决的问题 | 完成标准 |
| --- | --- | --- |
| A. 画工作流并修订汇报 | 现有闭环使用冻结规格和已审查的原生算例。需要明确新流程在哪些步骤能自行构造任务，哪些步骤复用现有组件。 | 一页流程图标出规格、网格工具、程序生成、求解、独立检查和归档。每个模块标注实际入口、输入输出及失败处理。汇报数字标明实验路径、分母与基线。 |
| B. 冻结 Markdown 问题规格 | 从自然语言取出的边界、源项或误差范数可能有歧义。 | 写出首个 `problem.md`，包括几何、方程、系数、源项、边界分组、误差范数与容差。适用于时变问题时写明初始条件。把已确认字段映射到 StudySpec 并保存摘要。关键字段缺失或不受支持时给出明确状态。 |
| C. 从几何生成初始网格 | 既有 Gmsh 导入能力有明确的几何和边界范围。新流程需要从几何出发制造可核验的初始网格。 | 留存网格生成脚本、参数和网格文件，检查连通性、区域面积与边界标记的覆盖。用 MFEM 检查导入结果，并记录任何后续加密。 |
| D. 生成、编译并运行 MFEM 程序 | 注册算例的现有入口不足以展示输入驱动的程序生成。编译通过也无法确认弱形式和边界实现正确。 | 交付生成的 `main.cpp`、源项与边界实现、构建命令和运行日志。输出离散阶次、组装方式、求解器与预条件子选择及理由。首轮可用有证据支持的标准配置。 |
| E. 做官方对照与错误边界负例 | 错误边界条件可能产生另一道题的收敛解。仅看残差或多层收敛可能放行。 | 先完成并冻结生成结果，再在匹配的模型、配置和指标下运行官方基线。正例达到预先声明的容差。负例故意误写边界类型、边界值或边界分组之一，保留其残差和收敛记录，并证明独立检查能定位规格与实现的差异。对照尽量读取状态与实际场，避免只比求解器自报的数字。 |
| F. 归档并可视化 | 演示需要能复现，也要让读者看出哪些门槛是实际检查过的。 | 从干净输出目录按文档运行，保存规格、网格、源码、构建参数、选择记录、结果场、验收报告和可视化。给出复跑与重放命令，标出与官方基线一致的指标和差异。 |

**下次汇报建议交付**　一个从 `problem.md` 到结果图的正例，一个会被拦截的边界错误负例，一张官方基线对照表，以及一张更新后的工作流图。A100 或 V100 资源可用于后续性能实验，首轮功能演示从现有 CPU 环境开展。

**汇报数字修订**　30/30 来自 6 个留出算例各重复 5 次，归档仍有 5 次重试。284 条验证测试包含 215 个故障样本和 69 个正确对照。CFAC 的耗时比 0.744 和 0.847 分别以筛查前稀疏 CFAC、同后端经典自适应停止为基线。[策略实验](E3_PERFORMANCE_ADAPTIVE.md) · [故障与对照](VERIFIER_CHALLENGE.md) · [CFAC 对照实验](CFAC_SPARSE_RESULTS.md)

## P1 · 首例通过后要解决的技术问题

| 问题 | 要做的验证 | 交付物与验收条件 |
| --- | --- | --- |
| 方案选择在什么条件下成立？ | 建立全组装、部分组装、无组装的能力表。结合算子性质、设备构建与内存约束验证 PCG、GMRES、Jacobi、AMG 等候选组合。固定问题、离散精度和验收条件比较可用组合。 | 至少一组等精度配对对照，注明拒绝或回退原因。记录端到端耗时、峰值内存、迭代次数与验收结果。 |
| 预测误差、残差和认证上界怎样接起来？ | 预测结果用于候选筛选，残差用于诊断代数收敛，验收使用与规格一致的指标。对 CFAC 先使用已有可复现的椭圆算例，说明能量范数、平衡通量、载荷与舍入条件。上界低于或等于容差可以验收。残差见证给出下界，否决整个原空间前还要扣除代数误差平方上界。 | 一页定义和推导、一个带独立检查结果的复现实例、一张验收及未定分支表。`L2` 或工程指标单列验收条件。 |
| 超差时应继续迭代、改善通量还是加密？ | 在同一冻结问题与容差下，对照继续原场迭代、固定原场优化 RT1 通量、加密原网格三种动作。用归档解释每次决策依据、检查开销和未通过的结果。 | 记录原场是否变化、证书上界是否变化、总耗时以及最终是否达标。保留未定和失败样本。 |
| 规模瓶颈在哪一段？ | 分开计时网格、组装、求解、证书构造和独立检查。在小案例对齐精度和输出后，再扩大规模或比较串行、MPI、GPU 审计及设备端求解。 | 报告环境、DOF、进程数、各阶段耗时、内存与最终验收。1,640,961 DOFs 的流式参考验算与 101,761 DOFs 的 CFAC 模块诊断各自列示。备选优化包括保守舍入批积分与 AMG，按准确性回归与等精度计时验证收益。 |

## P2 · 扩展官方算例和多物理场耦合

- [ ] 建立官方算例覆盖表，逐步扩大自主求解范围。为每个算例记录方程族、网格、离散、验收依据和所缺能力。可先扩展到已有独立核验基础的 Example 6，覆盖 AMR、悬挂节点和 Neumann 项。[现有 AMR 证据](E3_PERFORMANCE_ADAPTIVE.md)
- [ ] 从 MFEM MiniApps 或公开基准选一个范围清晰的耦合问题。可先评估热–流，明确耦合项、采用单向还是双向耦合、边界与初始条件、稳定性要求和参考结果。
- [ ] 按方程族定义验证指标，例如能量误差、守恒和平衡量。进入工程示范时，增加可获得的参考模型、观测或实验数据，并记录偏差来源。

## 交付检查

- [ ] Markdown 规格能追溯到实际网格、边界实现和程序版本。
- [ ] 可用一套命令生成、构建、运行和复核首例，并重放归档结果。
- [ ] 正例在冻结容差下通过，错误边界负例在独立复核时被拒绝。
- [ ] 可从产物回答三个问题：智能体生成了什么，官方基线验证了什么，误差认证的保证覆盖到哪里。
