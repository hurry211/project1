# MFEM 自主求解现存难点与组会复盘

**复盘范围**　2026 年 11 月 27 日组会。时间是逐字稿中的定位标记。项目现状以仓库已发布的实现和实验归档为准。每节的验证办法是根据组会要求拟定的工作，待有可复现证据后再结项。

老师认为现有工作是个好的开始。下一步应把需求从**对已知算例进行选型和复核**推进到**根据问题描述自主完成数值研究**。输入给出方程和几何后，系统应能选择工具、生成初始网格和求解程序，完成有限元计算，并独立核对生成程序解的是原问题、交付的解达到指定精度。先用 MFEM 官方 `examples` 建立可信的工作流，再逐步进入 MiniApps 和真正的多物理场耦合。（32:33–42:38、52:42）

## 一、自主求解工作流还缺哪些环节

### 1. 从 Markdown 问题描述到可执行规格

- **老师的要求（31:09–31:36、33:39、38:37–43:41）**　把智能体从输入开始走的整条工作流说清楚。输入文件要写明方程、区域、边界条件、初始条件和源项，再由系统决定后续调用。老师还问了哪些内容由模型完成、用的是哪个模型。各模块应能解释用途和功能边界。
- **当前难点**　已发布流程用 StudySpec 冻结结构化输入，并用注册表绑定已有 C++ 算例。可选模型在审查过的模板中提议，负责验证的程序再独立裁决。自主求解还需要把几何、方程和精度要求从输入映射到明确的计算合同，分清用户约束和智能体可以选的配置。[现有规划器](PLANNER.md) · [规格与验证约定](MVP_SPEC.md)
- **验证办法**　准备一个 `problem.md` 和对应的结构化规格。记录方程、系数、源项、每个边界组的条件、适用时的初值、验收范数和容差，保存冻结摘要。缺少关键字段或超出支持范围时，输出具体待确认项。记录模型和版本、实际参与的步骤及确定性核对环节。变更网格、阶次等计算选择时，仍能核对问题数据与验收标准。

### 2. 从几何描述生成初始网格，并保留正确的边界映射

- **老师的要求（33:39–35:14、41:02–41:57）**　给出几何后，由智能体找合适的网格工具生成初始网格，再交给 MFEM 离散。要把初始网格生成与求解过程中的网格加细都接到同一条流程里。
- **当前难点**　仓库已有受限的 Gmsh 导入和 MFEM 加密案例。由用户输入生成新网格时，还要把几何上的边界面与网格物理组一一对应。即使文件能导入，边界编号遗漏、交换或区域划分错误也会改变后续计算。[现有 Gmsh 导入约定](MVP_SPEC.md#10-stage-2-scalar-diffusion-and-named-meshes)
- **验证办法**　从一个二维几何起步，归档网格脚本、生成参数、物理组表和网格文件。检查区域覆盖、单元连接、边界段与物理组的映射。加一例边界标签交换，检查器应能指出哪一段不一致。后续加密时继续检查关键边界标记。

### 3. 生成的 MFEM `main` 能否忠实实现原问题

- **老师的要求（35:14–35:54、41:57、52:42）**　智能体要能按 MFEM 算例的调用顺序写出 `main`，包括右端项等配套函数，并复核生成代码本身。输入换成一个有新几何或新条件的问题时，应当能重构程序。
- **当前难点**　现有固定原生程序已有明确的弱形式与验证合同。面向生成程序，需要核对有限元空间、积分器、扩散系数、右端项、Dirichlet 约束与 Neumann 通量的实际实现。源码能编译、字段名写对或日志显示收敛，都不足以证明相应数学对象被正确组装。[已验证的原生算例](IMPLEMENTATION_STATUS.md)
- **验证办法**　保存生成源码、构建命令、依赖版本和可复用模块。对首个问题建立“规格字段、实现位置、独立检查”对应表。让检查器从冻结规格构造参考边界、载荷和算子检查，避免只读生成端自己给出的说明。分别用正确实现和故意改错的实现检查这条链。

### 4. 组装模式、求解器和预条件子的选择依据

- **老师的要求（36:13–37:50、41:57）**　考虑全组装、部分组装和无组装三种模式。求解器和预条件子也要能按条件选择，例如 PCG 或 GMRES，以及 Jacobi、AMG 或区域分解相关方案。选完还要复核结果。
- **当前难点**　已有部分组合在特定几何、方程和后端上测过。换算子、边界条件、单元或设备后，可用组合和成本都可能变化。例如 PCG 需要相应的对称正定条件。当前的选型证据还需扩展到生成程序与新网格，决定依据也需要能追溯。[能力矩阵与回退](IMPLEMENTATION_STATUS.md) · [实际计时约定](VERIFIED_PERFORMANCE.md)
- **验证办法**　先建立按算子、离散、组装模式与后端索引的能力表，说明每个候选的条件和不兼容时的回退动作。首例选一组有证据的配置。在同一问题、同一精度和独立验收条件下比较可用组合，记录组装、迭代、验算耗时与峰值内存。

## 二、两层验证与无解析真解的困难

### 5. 边界条件写错，为什么解仍能收敛

- **老师的原问题（51:36–52:42）**　如果智能体在生成代码时把边界条件写错，求解器可能在解另一个方程。不同网格和阶次上的计算仍可能收敛，对那个问题构造的误差区间甚至可能通过。需要定位误差发生在问题实现、离散还是求解环节。
- **当前难点**　现有故障实验与参考复算证明了既定问题族中的若干检查能力。生成代码引入了额外的语义问题。验收必须追溯到原始输入，先查所解问题，再查解的误差。若参考程序也从同一份错误实现取得边界，两条路径可能共同通过。[故障实验与对照](VERIFIER_CHALLENGE.md)
- **验证办法**　为同一冻结规格保留一组正确程序和一组故意改错边界值、类型或分组的程序。两组都正常运行，并保留残差及网格收敛记录。独立检查器根据原规格定位差异，正确组达到预设容差，错误组在问题一致性检查中被拒绝。后续用漏源项、系数符号或通量方向错误扩展该测试。

### 6. 官方算例怎么用，复核才能提供独立证据

- **组会要求（36:51–38:12、40:26–41:57、48:52–50:47）**　老师要求先复现 MFEM 官方算例并对流程多轮复核。讨论中补充了盲对照做法，让系统先根据问题构造自己的解，再用官方测试或程序输出核对。该补充在转写中的发言归属存在不确定性。
- **当前难点**　已有脚本可运行官方 Example 1，已有的制造解与官方常数源项问题有不同的验证合同。两个结果只有在模型、目标量和离散配置匹配时才能做相应比较。单组官方结果也只能为该算例提供外部对照。[官方基线脚本](../scripts/run_ex1_baseline.sh)
- **验证办法**　建议先选二维 Example 1，冻结 `f = 1`、几何、边界、阶次和比较标准。系统生成并运行求解程序后，保留源码提交，再让官方基线在同一网格与配置上运行。比较实际场或预定指标，记录各自的实现、配置和验收结果。将官方对照、独立问题一致性检查和结果精度检查放进同一份可重放证据。

### 7. 真误差未知时，后验信息怎么支撑硬容差

- **老师的追问（19:15–19:52、45:20–46:16）**　所谓“未见”是什么？如果验收要求误差低于某个容差，而真实误差未知，拿到的是残差等后验信息，靠什么判断达标？下界如何计算，用来衡量的具体量又是什么？
- **当前难点**　预测误差可筛方案，代数残差描述当前离散系统解得怎样。两者都需要明确如何关联到指定范数下的连续问题误差。现有策略实验的“未见”按算例 ID 留出，6 个留出算例各重复 5 次，可用于衡量已测范围的选型表现。这个结果需要和每次运行的独立误差验收区分。[策略评价与留出定义](E3_PERFORMANCE_ADAPTIVE.md#3-separated-risk-aware-adaptive-decision-evaluation)
- **验证办法**　对可认证算例冻结目标范数与容差 `τ`。报告当前近似解、可复算的上界 `U`、下界 `L` 和使用条件。同一范数下 `U ≤ τ` 才能凭上界验收，`L > τ` 可以判当前候选场超差，`L ≤ τ < U` 时保留未定。制造解用作事后校对，运行时由冻结数据和后验检查提供证据。[CFAC 数学规范](CFAC_MATHEMATICAL_SPEC.md) · [稀疏筛查推导](CFAC_SPARSE_METHOD.md)

### 8. CFAC 的证书覆盖哪一类方程，超差时该改哪里

- **老师的追问（30:26、44:16–48:18）**　CFAC 的名称、定义和依据是什么？能量误差由什么定义，能否处理其他指标？老师指出椭圆方程的能量来自相应双线性型，时变和耦合情况也需要解释能量如何定义。
- **当前难点**　CFAC（Certified Floor-Attribution Control）是项目对该控制策略的命名。已有原型针对受限扩散类问题，使用平衡通量与独立检查给出能量误差上界。上界偏大可能来自原场未充分迭代、原离散空间不足、通量构造未充分收紧或通量空间本身过粗。`L2`、时变与工程量的验收需要各自的依据。[CFAC 数学规范](CFAC_MATHEMATICAL_SPEC.md) · [未解问题](CFAC_OPEN_PROBLEMS.md)
- **验证办法**　先在受限椭圆算例上写清双线性型、能量范数、平衡通量、载荷和舍入假设。在固定问题与容差下，分别测原场续算、固定原场换通量和网格加密能改善哪个量。若要证明整个原离散空间无法达标，用残差见证的平方下界扣除代数误差平方上界，再与 `τ²` 比较。阈值未被判定时记录为未定，保留下一步的动作依据。[固定原场实验与诊断](CFAC_SPARSE_RESULTS.md)

## 三、工程扩展的难点

### 9. 规模、算力环境和端到端瓶颈尚需定位

- **老师的追问（22:35–23:01、27:31–27:55、38:37、54:01）**　实验在哪种环境下做的？“十万级有理数复核”里的量是什么，十万与百万说的是自由度还是网格？如本地资源吃紧，可用实验室远程环境试验。
- **当前难点**　已发布的 1,640,961 DOFs 对应流式参考验算，101,761 DOFs 对应 CFAC 模块诊断，后者的归因仍为未定。十万规模时，稀疏归因与精确复核合计 63.26 s。筛查能减少证书构造次数，但对同后端经典停止的耗时比区间仍跨 1，还存在较慢和未验收的算例。[流式参考验算](E3_PERFORMANCE_ADAPTIVE.md) · [CFAC 对照与规模证据](CFAC_SPARSE_RESULTS.md)
- **验证办法**　从同一算例的小规模可复现测量开始，逐段测网格、组装、求解、证书构造、独立检查、首次失败与重试。报告单元数、DOFs、进程数、设备、峰值内存和最终状态。比较 CPU、MPI 或 GPU 时标清执行环节及相同验收标准。算力扩展与等精度加速可在首个闭环跑通后推进。

### 10. 多个独立方程怎样推进到真正耦合

- **老师的追问（28:50–29:30、32:33–33:07、38:12–41:02）**　有没有流体？热、波、三维线弹性分别做了哪些方程，是否存在组合？后续要走向热与流体、物质输运或电场与流体这类相互作用的问题。先把基础 `examples` 的流程做熟，再考察 MiniApps 和更复杂的算例。
- **当前难点**　已有热、波与线弹性覆盖提供了独立方程的复算基础。一个耦合算例还需要明确场之间交换什么量、更新顺序、时间步和迭代如何控制，以及接口或守恒量如何检验。[已覆盖的方程族](RESULTS.md) · [各阶段已验证范围](IMPLEMENTATION_STATUS.md)
- **验证办法**　维护官方算例覆盖表和能力缺口。先扩展到不同边界与 AMR 的基础算例，再从 MiniApps 或公开基准冻结一个低复杂度耦合问题。写明两个子模型、耦合项、初始与边界条件、参考结果和验收量。检查子模型的独立结果，并验证耦合项启用后出现预期的物理变化。

### 11. 工程问题怎样做物理与业务校验

- **老师的要求（46:16–48:18、50:47–51:36）**　评价标准要随问题变化。老师举例，流体中的耗散率场和 Kolmogorov 尺度可能用于指导网格细化。模型应用还可通过其他模型、历史观测或卫星数据比较，检验计算在实际情境中的有效性。
- **当前难点**　椭圆算例的能量证书只能回答其条件下的误差问题。工程判断还要决定什么量对应用有意义、参考数据是否可对齐，以及数值偏差、模型偏差、观测不确定性分别有多大。
- **验证办法**　每个新问题预先确定观测量、比较域和时间窗口、基准来源、误差或守恒阈值。对有数据的问题写清匹配方式和数据不确定性，并把数学验算、物理一致性和与参考数据的比较分别记录。

## 建议处理顺序与结项证据

- [ ] **首个里程碑 · 先解决难点 1–6。** 交付一个基础官方算例的端到端归档，包含冻结 Markdown、几何与网格脚本、生成源码、选择依据、实际场、可视化、官方对照和错误边界负例。第三方可从干净目录复跑并得到相同的验收结论。
- [ ] **第二个里程碑 · 解决难点 7–9。** 至少复核一个无真解认证案例，把上界、下界、未定状态和输入一致性串起来。再用等精度对照定位成本，明确哪些结论已有证据、哪些只在实验范围内观察到。
- [ ] **第三个里程碑 · 展开难点 10–11。** 按能力覆盖表扩充官方算例，进入一个 MiniApp 或公开耦合基准，交付数学检查、耦合检查及物理对照证据。
