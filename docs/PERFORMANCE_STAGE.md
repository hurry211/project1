# MFEM 性能与扩展阶段实验

本阶段以 `hurry211/project1` 的 `main@52fed54` 为基线。对照原规划和导师补充意见，MFEM 负责有限元装配与求解，工作流负责资源分配、选型、独立验证和归档。实验分别检验装配模式的影响、重试编排的开销以及一个明确的各向异性扩散算例。

仓库另有 `research/stage2-performance@b7b4ec7`，包含独立的性能入口和强跳跃分层扩散原型，分支文档将后者标为待原生验证。本阶段从默认分支起步，实测范围为接入正式控制器的 Poisson 和各向异性制造解。两条分支的实验结果各自归档。

## 原版复现

在 Ubuntu 24.04 WSL2 上使用 GCC 13.3.0、CMake 3.28.3 和 Python 3.12.3。MFEM 使用 GitHub 固定提交 `d964264cdb9a13e94a201b6c236c7721e0c8765f` 的发布源码归档，SHA-256 为 `60a20488b357cb77d9bb85b12bf863b3fc634bab8cd0b6167500666aa93fcf64`。以仓库构建脚本的串行、双精度、Release 参数编译。Python 依赖使用受哈希约束的仓库锁文件。

原版通过全部 151 项测试。历史 31 组任务的终态、重试裁决、冻结输入和原失败码匹配，68 个受比对的已验收误差范数最大相对差为 0。Quickstart 的重新验收和归档重放均通过。

## 如何复现

按 [README](../README.md) 构建固定版本的串行双精度 MFEM 和求解器。在新的运行目录执行以下命令。

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
python -m pytest -q --require-mfem
python -m sciagent quickstart --runs-dir runs/stage-quickstart
RUNS_DIR=runs/stage-demo bash scripts/run_demo.sh
python scripts/compare_baseline.py runs/stage-demo
python -m benchmarks.robustness --generate-controls runs/stage-controls --report runs/stage-challenge.json
taskset -c 2 python -m benchmarks.performance --output runs/performance --repeats 5
taskset -c 2 python -m benchmarks.performance --mixed-boundary --output runs/performance-mixed --repeats 5
taskset -c 2 python -m sciagent search specs/experiments/strategy_poisson.json --output runs/strategy --repeats 3
python -m sciagent run specs/extensions/anisotropic_1000_q1.json --runs-dir runs/anisotropic
```

`taskset -c 2` 将计时固定在同一个逻辑 CPU 上。在其他机器上可使用该机器允许的逻辑 CPU 编号。

## 装配与重试对照

- 装配对照使用同一个 Poisson 制造解、全 Dirichlet、相同四边形网格、相同阶次和 CG + Jacobi，CG 相对容差为 10⁻¹²，绝对容差为 0。分别测 Q1 和 Q2，网格每边划分为 [8, 16, 32] 或 [16, 32, 64]。每组独立预热一对，再交替运行顺序，测量五对。两种配置都须独立验收，逐级 L² 和 H¹ 半范数误差须在 10⁻⁷ 相对容差内一致。
- 另用原仓库的 $\cos(\pi x)e^y$ 混合边界算例对照 [16, 32, 64] 上的 Q1 和 Q2，以覆盖需要更多 CG 迭代的输入。
- 装配耗时计入 MFEM 刚度算子构造和 Dirichlet 约束线性系统的形成。右端项、预条件器、CG 迭代、求解器自报误差、文件导出分别计时。验证耗时包含新进程启动、独立积分与参考求解、验证结果返回。端到端时间从调用控制器到清单落盘，包含文件校验和归档。各阶段用时以该次试验所有实际分级执行的总和统计。
- 峰值常驻内存使用 Linux `/proc/self/status` 的 `VmHWM`，分别取求解器进程和验证器进程的最大值。该值对应可执行程序的地址空间，避免把启动进程继承的内存算给求解器。控制器常驻集和全进程树同时占用量未测。进程内存预算使用 `RLIMIT_AS`，限制虚拟地址空间。
- 重试对照用同一可执行文件、同一独立验证进程和原有的重试输入，唯一变量是能否复用。只有独立验收确认仅差精度的级别才参与复用。新尝试复制完整目录并校验字节，沿用本轮独立验证过的单级报告。整体验收仍检查所有层级的收敛阶和精度。复核归档时从全部原始数据重新独立计算，已有归档按原哈希规则读取。

## 最小扩展与选型基线

扩展算例在单位方形上求解 $-\nabla\cdot(A\nabla u)=f$，其中 $A=\operatorname{diag}(1000,1)$，$u=\sin(\pi x)\sin(\pi y)$，$f=1001\pi^2u$。系数比固定为 1000，所有边界由精确解给出 Dirichlet 数据。C++ 注册信息包含方程、精确解与源项，Python 以三者匹配后绑定。独立验证器用差分检查制造解源项，并按方向加权重新组装刚度矩阵、求解并对照 MFEM。只登记串行全装配 Q1 CG + Jacobi。错误源项须被独立参考解拒绝。

选型基线穷举能力矩阵允许的四个候选，组合为 Q1/Q2 与全/部分装配，固定 CG + Jacobi。起始自由度超出求解或独立参考求解预算的候选提前排除。同一目标和资源策略在每次试算冻结。只有每次重复都得出 `ACCEPTED` 的候选参加排序，按端到端用时中位数升序，平局按标识符排序。候选与裁决规则固定，实测时间会随机器和负载变化。

## 串行 CPU 实测

实验机器为 AMD Ryzen 7 7840H，WSL2 可用内存约 7.35 GiB，计时锁定一个逻辑 CPU。表中时间为五次实测的中位数，方括号为最小值和最大值。比值取每一对端到端时间的第一项除以第二项，再取五个比值的中位数。

| 制造解与离散 | 最细自由度 | 全装配端到端（秒） | 部分装配端到端（秒） | 全 / 部分 |
| --- | ---: | ---: | ---: | ---: |
| 正弦 Q1，n=32 | 1,089 | 0.522 [0.497, 0.576] | 0.569 [0.536, 0.576] | 0.917 |
| 正弦 Q1，n=64 | 4,225 | 0.764 [0.737, 0.806] | 0.761 [0.710, 0.787] | 1.024 |
| 正弦 Q2，n=32 | 4,225 | 0.657 [0.635, 0.683] | 0.641 [0.620, 0.648] | 1.025 |
| 正弦 Q2，n=64 | 16,641 | 1.296 [1.169, 1.426] | 1.251 [1.224, 1.305] | 0.993 |
| 混合边界 Q1，n=64 | 4,225 | 0.918 [0.860, 0.992] | 0.948 [0.932, 1.006] | 0.937 |
| 混合边界 Q2，n=64 | 16,641 | 1.454 [1.435, 1.513] | 1.455 [1.440, 1.536] | 0.994 |

正弦 Q2、n=64 的多级装配中位数从 17.78 ms 降至 6.14 ms。预条件器设置从 0.224 ms 升至 0.457 ms，CG 从 1.57 ms 升至 3.64 ms。求解器峰值 RSS 从 18.86 MiB 降至 15.02 MiB，验证器峰值约 170.6 MiB，最细层均为 8 次 CG 迭代。独立 L² 误差为 4.8092×10⁻⁷，H¹ 半范数误差为 1.9948×10⁻⁴。独立验证用时中位数约 0.93–0.97 秒，占据端到端成本的大部分。

混合边界 Q2、n=64 的最细层均为 358 次 CG 迭代。部分装配使多级装配中位数从 18.72 ms 降到 5.83 ms，同时 CG 中位数从 63.73 ms 升到 135.18 ms。30 对装配试验均保持独立验收及误差等价。混合边界 Q1 的五个端到端比值全部低于 1，另外五组的观测范围均包含 1。小规模串行 CPU 数据支持按案例选择装配，部分装配的装配收益没有稳定传递到整个工作流。

重试试验的 4 次尝试保持相同的决策序列和最终 L² 误差 8.45221×10⁻⁵。复用把 MFEM 启动和单级独立数值计算均从 18 次降至 6 次。端到端中位数从 4.253 秒降至 3.466 秒，五个配对的加速比中位数为 1.198，范围 [1.111, 1.255]。验证阶段中位数从 3.314 秒降至 2.744 秒。每次尝试仍保留完整文件副本，归档空间未作为优化目标。

## 各向异性与策略选择结果

各向异性制造解在 n=8、16、32、64 上通过独立验证，最细两层测得 L² 收敛阶 1.99998，H¹ 半范数收敛阶 0.99991。最细网格 L² 误差为 1.18793×10⁻⁴，与独立参考解相对差为 2.46×10⁻¹³。错误源项回归测试触发 `REFERENCE_MISMATCH`。这个光滑解适合核对张量算子实现，更多载荷方向、界面跳跃、奇异域和各向异性预条件仍需各自的数学基准。

固定 L² 目标 10⁻⁴ 和一次尝试时，两个 Q1 候选的最细误差均为 4.752×10⁻⁴，均耗尽精度重试额度。两个 Q2 候选的最细误差均为 3.847×10⁻⁶，三次试算均获验收。全装配和部分装配中位数分别为 0.626 秒和 0.614 秒，规则选择 Q2 部分装配。本次穷举总耗时 7.12 秒，约 0.012 秒的候选差距只用于本次排序。

## 回归结果及后续

原有 151 项测试全部保留。新增 7 项专项测试，能力矩阵新增的两个组合也自动进入参数化测试，合计 160 项通过。历史 31 组任务全部匹配，68 个已验收误差范数最大相对差仍为 0。验证器挑战复跑了 284 个样本和 14 个参考检查器校准样本。215 个有故障样本全部拒绝，69 个干净样本全部接受。

独立预算试验使用混合边界 Q2、全装配 CG + Jacobi、网格 [32, 64, 128] 和验证超时 60 秒。两次试验的三个 MFEM 层级均成功。验证地址空间限额为 256 MiB 时，工作流因 `VERIFIER_MEMORY_LIMIT` 拒绝验收。限额为 1,024 MiB 时通过，验证器峰值 RSS 为 528.5 MiB。超时拒绝另由回归测试覆盖。

原始对照统计、预算试验输入、策略结果、历史比对与测试日志见 [evidence/performance-stage](../evidence/performance-stage/)。包括原始场数据在内的完整运行目录保留在本机 WSL2 的 `/home/fy/project1-stage/final/runs`，统计文件记录了各次归档的清单摘要。

下一步优先在更大自由度及更多载荷下复测装配与求解成本，再用高对比度分层扩散原型检查界面通量和能量。独立验证是当前主要耗时，应比较分块积分、稀疏参考求解及独立残差复核的成本和故障检出率。当前 WSL2 可见 RTX 4060 Laptop GPU，但未配置 CUDA 工具链，固定 MFEM 构建为串行 CPU，且环境无 `mpirun`。MPI、CUDA 和 LLM 选型均留待后续的独立对照。
